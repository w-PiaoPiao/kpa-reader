# 口袋阅读 · PocketReader

专为 **KONKR Pocket Advance** 做的安卓电子书阅读器。

那台机器是 3.5 寸 960×640 的横屏安卓掌机，有完整的实体按键（十字键 / ABXY / L1R1 / L2R2 / START / SELECT）。
用手机阅读 App 在上面读书，最大的问题不是屏幕，而是**所有操作都得用手指去戳一块 3.5 寸的触摸屏**。
所以这个阅读器从第一行代码起就按「纯手柄操作」设计：翻页、换章、开目录、切主题、加书签，全程不碰屏幕。

支持 **TXT / EPUB / MOBI / AZW3**，带**全文搜索**和**插图渲染**。

---

## 安装到掌机

1. 把 `app/build/outputs/apk/release/app-release.apk` 传到掌机（U 盘 / 微信文件传输助手 / 网盘都行）
2. 在掌机的文件管理器里点开这个 APK 安装（允许「安装未知来源应用」）
3. 打开「口袋阅读」，点右上角 **+ 导入**，选一本书

> **导入时看不到 mobi / azw3？** 不是不支持。Android 把 `.mobi` 认成「PRC 文件」、
> `.azw3` 认成「BIN 文件」，它们**不属于「文档」分类**，「最近」列表也不索引。
> 请在文件选择器里点左上角菜单 → **下载**（或「设备存储」），再点右上角把网格切成**列表视图**，
> 就能看到并按名称点选。已实测 MOBI / AZW3 导入正常。

> 最低要求 Android 8.0，掌机出厂是 Android 12，直接可用。

## 按键

### 阅读中

| 按键 | 作用 |
|------|------|
| 十字键 ← / ↑ | 上一页 |
| 十字键 → / ↓ | 下一页 |
| A / R1 | 下一页 |
| L1 | 上一页 |
| L2 | 上一章 |
| R2 | 下一章 |
| X | 目录 |
| Y | 全文搜索 |
| START | 呼出 / 收起菜单 |
| SELECT | 夜间模式开关（再按回原主题） |
| B | 后退（**连按两次**才返回书架，防误触） |
| 触摸 | 左 1/3 上一页，右 1/3 下一页，中间呼菜单；左右滑动也能翻页 |

### 菜单打开时

十字键在按钮间移动焦点（当前项有金色描边），**A 确认**，**B / START 收起**。
菜单：目录 / 搜索 / 书签 / A- / A+ / 主题 / 昼夜 / 设置。

**设置面板**（单列）：字号、行距、左右边距、上下边距、衬线字体开关、页眉页脚开关、按句分段开关、全书跳转。
滑块松手即生效，关掉页眉页脚就是纯正文满屏。

面板所有项都能纯手柄操作：十字键上下换项，**左右键调滑块 / 切开关**，**A 确认**。
（做成单列就是为了这个 —— 分成两列时左右键被滑块吃掉，右列永远选不中。）

### 书架

十字键移动焦点（选中的卡片有金色描边），**A 打开**，长按删除，Y 看说明。
书卡显示：书名 / 作者 / 格式 / 章数 / 进度 / 最近阅读日期。

## 功能

### 格式

| 格式 | 说明 |
|------|------|
| **TXT** | 自动识别 UTF-8 / UTF-16 / GBK / GB18030；清除行首多余缩进 |
| **EPUB** | 正文 + **插图 + 封面**；目录优先取 nav.xhtml，退回 toc.ncx；标题层级保留 |
| **MOBI** | 无压缩 / PalmDOC LZ77 / HUFF-CDIC 三种压缩；EXTH 元数据；内嵌图片 |
| **AZW3** | 同 MOBI（KF8 容器的 dual-format 走 MOBI7 部分） |

### 阅读

- **分页**：段落流式分页，中文首行缩进两字，跨页续段不重复缩进
- **按句分段**：开关一开，长自然段拆成一句一行 —— 每句都缩进两字，句间不加额外间距。
  只改排版边界不动字符，进度、书签、搜索的位置完全不受影响；标题和引用保持原样
- **插图**：按页宽等比缩放、居中；比整页还高的图单独占一页；位图走 LruCache
- **全文搜索**：后台扫描全书，结果带章节归属 + 上下文，关键词红色高亮，点一下跳过去
- **章节**：自动识别「第X章 / 第X回 / 第X卷 / 序章 / 楔子 / Chapter N」；EPUB/MOBI 用内置目录
- **主题**：纸白 / 护眼 / 夜间 / 纯黑，记日间主题，一键切夜间再一键切回
- **进度**：按**全书字符偏移**保存，换字号、重排版后仍能精确回到同一句话
- **书签**：存位置 + 一小段预览文字
- **跳转**：百分比滑块，或直接从书签跳
- **缓存**：导入时把正文和图片抽出来存进 App 私有目录，原文件删了/移了照读不误

## 为这块屏幕做的几件事

**960×640 = 240×160 的 4 倍**，3:2 比例。默认 16sp 接近小开本实体书的密度，一屏 8~9 行。

**行距参数不是拍脑袋定的**。`StaticLayout.setLineSpacing` 的 multiplier 乘的是字体 metrics 高度，中文衬线字体约 1.37em —— 所以设成 1.15 才是视觉上的 1.57 倍行距。早期按 1.35 设，实际渲染出接近 2 倍行距，一屏只剩 5 行。

**`setIncludePad` 必须为 true**。为 false 时 `layout.height` 比真实绘制范围小，按它累加页高，最后一行会压到页脚上（实测被切掉半截）。

**按键去抖**。部分固件（以及 `adb input`）会把一次按下报成两个 `ACTION_DOWN`，夜间模式这种开关会瞬间被切回去。非连发动作统一加 260ms 去抖，翻页类才允许按住连发（80ms 一次）。

**搜索用覆盖层而不是 Dialog**。Dialog 的 window 收不到 IME inset，横屏软键盘一弹就把输入框盖住；改成 Activity 内的 View，自己监听 `WindowInsetsCompat.Type.ime()` 抬高底部。键盘在这块屏上要吃掉七成高度，所以输入时只留输入框，按搜索键收起键盘后再展开结果。

**输入法要关掉「全屏提取」**。横屏小屏上 IME 默认会把 EditText 提取成全屏编辑界面，把整个搜索界面顶掉 —— `IME_FLAG_NO_EXTRACT_UI`。

**分页放到后台线程**。一章几万字要排两百多页，同步跑在 UI 线程会明显卡住换章。为此 `LayoutEngine` 里的所有 Paint 都在构造时**深拷贝**一份，否则后台排版和界面改字号会撞车。

**图片不在 `onDraw` 里解码**。解码一张大图要上百毫秒，放在绘制里必掉帧；改成当前页图片后台预解，先画占位块。位图走 LruCache，尺寸探测只读图片头。

**书库写盘是异步的**。翻页每 0.7 秒更新一次进度，同步写整个 JSON 会卡主线程；改成单线程队列 + 请求合并，退出前 `flush()` 保证落地。

## MOBI 解析里最坑的一处

`extraDataFlags` 的理论读法（按位从记录尾部倒推变长整数）在 calibre 生成的书上会失效：
两个真实样本的 flags 都写作 `0x3`，但按 bit1 回读会把正文的 UTF-8 字节当成整数，解出 2 亿多的长度，直接把整条记录剥光。

实测出的可靠判据是：**PalmDOC 记录总是解满 4096 字节**，超出多少就该剥多少；只有最后一条（本身不足 4096）才用 bit0 给出的多字节重叠长度兜底。
另外正文必须**先拼字节流、按 `textLength` 截断，最后一次性 UTF-8 解码** —— 逐条解码会在记录边界切坏多字节字符。

用两本真实出版物（一本 MOBI、一本 AZW3）验证：76700 / 315306 字符，替换字符 0 个，首尾完整。

## 构建

```bash
./build.sh          # 出 release APK（已签名，可直接装）
./build.sh debug    # 出 debug APK
```

环境：JDK 17、Android SDK（compileSdk 36）、Gradle 9.x + AGP 9.1。
`build.sh` 会自动生成 `local.properties` 指向 `$ANDROID_HOME` 或 `~/Library/Android/sdk`。

签名证书和密码都不入库。要在本机签出可覆盖升级的包，把 `release.keystore` 放到项目根目录，
再在 `local.properties` 里补三行（`KEYSTORE_PASSWORD` / `KEY_ALIAS` / `KEY_PASSWORD`）。
不配也能构建，release 包会自动退回 debug 签名。

## 代码结构

```
app/src/main/java/com/kpa/reader/
├── MainActivity.kt              书架：网格、导入（SAF）、删除、手柄焦点
├── data/
│   ├── Book.kt                  书籍/章节/书签模型 + JSON 序列化
│   ├── BookStore.kt             书库持久化（原子写）
│   └── ReaderSettings.kt        阅读设置、四套主题
├── doc/
│   ├── Doc.kt                   Block / Document（纯文本 + 块序列）
│   ├── HtmlBlockParser.kt       容错 HTML → 块（标题/正文/图片/引用）
│   ├── SentenceSplitter.kt      句子切分（按句分段用，只算边界不动字符）
│   └── LayoutEngine.kt          分页引擎（文本块 + 图片块）
├── book/
│   ├── TextLoader.kt            编码探测 + 文本归一化
│   ├── ChapterSplitter.kt       章节正则识别 / 虚拟分章
│   ├── EpubParser.kt            EPUB 解包、图片、nav/ncx 目录
│   ├── MobiParser.kt            PDB / PalmDOC / HUFF / EXTH / KF8
│   ├── BookImporter.kt          导入流程（解析 → 落盘 text/blocks/img）
│   └── Paginator.kt             （旧版纯文本分页，保留兼容）
├── ui/
│   ├── PageView.kt              自绘渲染、翻页过渡、图片、触摸
│   ├── ReaderActivity.kt        阅读界面、菜单、目录、搜索、书签、按键
│   └── ShelfAdapter.kt          书卡
└── input/
    └── Gamepad.kt               键值 → 语义动作映射
```

**为什么用「块序列」**：文字、标题、插图要在同一套分页里排，纯字符串装不下图片。
但进度保存和全文搜索仍然只认**全书纯文本 + 字符偏移**，所以 `Document` = 纯文本 + 块（块用字符区间指向纯文本），两套坐标各司其职。

## 已知限制

- **纯 KF8 的 AZW3**（无 MOBI7 兼容部分）只能尽力提取文字，章节结构可能不准；dual-format 的 AZW3 走 MOBI7 部分，完全正常
- HUFF/CDIC 压缩的 MOBI 已实现，但手上没有样本，未实测
- 不支持 MOBI/AZW3 的 DRM（加了密的书会明确报错）
- 不解析 CSS 排版细节：图片位置、居中、字体样式按统一规则处理
- 单本导入上限 24MB（TXT）/ 图片总量 64MB（EPUB）
- 没做避头尾、中英混排间距、标点悬挂

后续可补：搜索历史、脚注链接跳转、TTS 朗读、双栏排版。
