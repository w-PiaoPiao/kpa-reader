## 口袋阅读（KONKR Pocket Advance 安卓阅读器）— 从零到可安装

**方向转折**：项目目录虽然叫 `GBA游戏/阅读器`，项目指令也写着「开发在 GBA 模拟器上跑的游戏」，
但用户明确要求 **基于安卓开发**。KONKR Pocket Advance 不是 GBA 自制软件，而是一台
Android 12 掌机（3.5" 960×640 3:2、Helio G90T、十字键+ABXY+L1R1+L2R2+START/SELECT，无摇杆）。
后续都按安卓原生 App 做，不要在 GBA ROM 方向返工。

### 构建链（踩了两个坑，务必复用这套配置）

- **Gradle 9.7.1（系统）+ AGP 9.1.0**，不要用 AGP 8.x：`AGP 8.x relies on Gradle internal API removed in Gradle 9.6.0`。
- **AGP 9 内置 Kotlin**，加 `org.jetbrains.kotlin.android` 插件会直接报错，必须删掉；
  `kotlinOptions` 也不需要。
- Gradle wrapper 生成不了：`services.gradle.org` 国内不通，wrapper task 会提前校验 distributionUrl 并失败。
  所以项目里**不放 wrapper**，`build.sh` 直接调用系统 `gradle`。
- 本机有 `~/.gradle/init.d/00-aliyun-mirror.gradle` 注入阿里云镜像 + `~/gradle-local-repo`，构建可用。
- 环境：JDK 17、SDK `~/Library/Android/sdk`、compileSdk 36、minSdk 26。
- 构建命令：`./build.sh`（release，已签名）/ `./build.sh debug`。

### 模拟器验证（必须在沙箱外跑）

Android emulator 需要写 `~/.android`，在沙箱里会被拦并卡死（QEMU thread hanging）。
必须 `dangerouslyDisableSandbox` 启动；参数用
`-no-window -no-snapshot-load -no-snapshot-save -gpu swiftshader_indirect`，
再 `wm size 960x640` + `wm density 320` + `user_rotation 1` 模拟掌机屏幕。

### 关键设计决策

- **分页**：`Paginator` 按段落流式排（每段一个 StaticLayout），不用整章 StaticLayout——后者对无章节的长 TXT 会 OOM。
  跨页用 `getLineStart` 断行，续段不加首行缩进。
- **行距陷阱**：`StaticLayout.setLineSpacing` 的 multiplier 乘的是**字体 metrics 高度**（中文字体≈1.37em），
  所以 1.15 才是视觉 1.57 倍行距。按 1.35 设会变成近 2 倍行距、一屏只剩 5 行（踩过）。
- **正文缓存**：导入时把正文抽成纯文本写进 `filesDir/books/<uuid>.txt`，原文件删了也能读，EPUB 只解一次包。
- **编码**：BOM → 严格 UTF-8 → GB18030 兜底。`TextLoader.normalize` 会清掉行首全角空格，
  否则会和引擎的 2 字缩进叠成 4 字。
- **进度**：存全书字符偏移（不是页码），换字号重排后仍能精确还原。
- **按键**：`Gamepad.actionOf(KeyEvent)` 做键值→语义映射；非连发动作加 260ms 去抖
  （部分固件/adb input 会把一次按下报成两个 ACTION_DOWN，夜间模式会瞬间被切回），翻页类才允许 80ms 连发。
  菜单打开时把 D-pad 让给系统做焦点导航，A 键手动转 `performClick`（手柄 A 不是 ENTER）。
- **目录弹窗自绘**：AlertDialog 的列表高度不受 `setLayout` 控制，横屏 640 只能露 4 行；
  改自定义 Dialog + `AbsListView.LayoutParams` 压到 38dp/行。

## v1.1：EPUB 完整化 + 全文搜索 + MOBI/AZW3

用户当天追加需求：「epub全部做，要有全文搜索，要支持MOBI/AZW3」。

### 架构改造：引入块模型

纯文本装不下图片，所以正文改成 `Document(text, blocks)`：
- `text` 仍是全书纯文本，**继续作为进度保存和全文搜索的唯一基准**（字符偏移）
- `blocks` 是渲染序列：文本块（带 style：正文/H1/H2/H3/引用）+ 图片块
- `Chapter` 增加 `blockStart/blockEnd`：**纯图片章节（封面）没有字符区间，只能靠块区间定位**
- 缓存落盘：`books/<id>.txt` + `books/<id>.blocks` + `books/<id>.img/`
- 旧数据没有 blocks 文件时用 `Document.blocksFromPlainText` 兜底

### MOBI/AZW3 实现要点（**最坑的地方**）

`extraDataFlags` 的理论读法（按位从记录尾部倒推变长整数）在 calibre 生成的书上会失效：
两个真实样本 flags 都写作 `0x3`，按 bit1 回读会把正文的 UTF-8 字节当整数解释，
解出 2 亿多的长度，**整条记录被剥光**。

实测出的可靠判据：**PalmDOC 记录总是解满 4096 字节** → 超出多少剥多少；
只有最后一条（本身 < 4096）才用 bit0 的 `(last & 3) + 1` 兜底。

另外正文必须**先拼字节流、按 `textLength` 截断，最后一次性 UTF-8 解码**——
逐条解码会在记录边界切坏多字节字符。

已验证样本：两本真实出版物（一本 PalmDOC/65001/57 记录的 MOBI、一本 MOBI7 容器的 AZW3，非 KF8）。
结果：76700 / 315306 字符，**替换字符 0 个**，首尾完整。

字段偏移（record0 绝对）：compression 0、textLength 4、recCount 8、recSize 10、
headerLength 0x14、mobiType 0x18、encoding 0x1C、firstNonBook 0x50、fullName 0x54/0x58、
firstImage 0x6C、huff 0x70/0x74、exthFlags 0x80、extraFlags 0xF2。

### 其他踩坑

- **XHTML 开头的 `<?xml?>`** 会被 HTML 解析器当正文显示，必须跳过 `<?`/`<!` 开的段。
- **NCX 路径**：`p.substringBeforeLast('/')` 在 ncx 位于根目录时返回整个文件名，
  拼出的 href 全错 → 目录标题全部退化成「第 N 节」。必须 `if (p.contains('/')) ... else ""`。
- **`setIncludePad(true)`**：为 false 时 `layout.height` 比真实绘制范围小，累加页高会让最后一行压到页脚上。
- **搜索 UI 不能用 Dialog**：Dialog 的 window 收不到 IME inset，横屏软键盘一弹就把输入框盖住。
  改成 Activity 内的覆盖层 + 自己监听 `WindowInsetsCompat.Type.ime()`。
  且键盘在 640 高屏幕上占七成，输入时只留输入框，按搜索键收键盘后再展开结果列表。
- **`IME_FLAG_NO_EXTRACT_UI`**：横屏小屏上输入法默认进入「全屏提取」模式，把整个搜索界面顶掉。
- **release 包 non-debuggable**，`adb run-as` 取不到数据；需要读内部文件时用 debug 包。
- 章节定位：`progressOffset == 0` 时直接取第 0 章，否则纯图片章节（封面）会被 `chapterIndexAt` 跳过。

## v1.2：全面优化（用户要求「还有哪些可以优化，全部做」）

### 性能（都是用户能直接感知的）

1. **`BookStore.persist()` 原本在主线程同步写整个 JSON**，翻页每 0.7s 阻塞一次。
   改为单线程后台队列 + `pending` 标志合并请求，`flush()` 在 onPause 等待落地。
2. **分页原本在 UI 线程同步跑**，换章要整章重排（200+ 页）→ 卡住。
   移到 `Dispatchers.Default`；为此 `LayoutEngine` 所有 Paint 构造时**深拷贝**
   （否则后台排版与界面改字号共用 Paint 会撞车）。分页未完成时用 `pendingChar`
   暂存位置，进度不跳变。
3. **图片在 `onDraw` 里同步 `decodeFile`** → 掉帧。改后台预解码 + 占位圆角块。
4. **`ChapterSplitter` 对每行都 substring**（77 万字 → 几万临时串）→ 先按行长筛选。

### 体验

设置面板（横屏两列：字号/行距/左右边距/上下边距/衬线字体/页眉页脚/跳转）、
页脚进度条、滑动翻页动画（170ms）、目录自动定位当前章、导入全屏进度 + 异常翻译成人话、
书架显示作者、防重复导入、书签去重、启动窗口底色跟随主题。

### 代码质量

删 `Paginator.kt`（被 LayoutEngine 取代）、`showKeyHelp()`、无用字段。
**新增 24 个单元测试**（`app/src/test/`）：章节识别 / HTML 解析 / 编码探测 / 块序列化。
测试跑出一个真 bug：`番外一`「外传2」这类带序号篇名识别不了 → 已修正则。

### 踩坑记录

- 设置面板单列放不下：`640 - 按钮 96 - padding 32 = 512px`，而「排版 4 滑块 + 2 开关 + 跳转」要 520px。
  试过压 padding、去小标题都不够，最后改成**横屏两列布局**才彻底解决。
