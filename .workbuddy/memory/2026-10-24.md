# 2026-10-24

## v1.6.1：设置里可改键，默认 R1 下章 / R2 上章

用户要求：「需要可以在设置中调整快捷键，默认 R1 下一章，R2 上一章」。

### 设计

新建 `input/Keymap.kt` 统一管映射，`Gamepad.actionOf()` 从"一大坨 when"改成
「先查用户绑定表 → 再落固定键」，这样改键立刻生效且不必动分发逻辑。

- **可绑**：A / X / Y / L1 / R1 / L2 / R2 / START / SELECT（共 10 个动作）
- **不可绑**：十字键（翻页导航基础）、B（后退键；捕获时也用作取消）
- **冲突处理**：绑到已占用的键时两者**交换**，而不是把对方置空 ——
  否则用户改一次映射就会莫名丢一个功能
- 存储：SharedPreferences `reader_keys`，键名用 Action 枚举名，缺省回落到默认表

### 默认映射（本次改动的重点）

| 键 | 旧 | 新 |
|---|---|---|
| R1 | 下一页 | **下一章** |
| R2 | 下一章 | **上一章** |
| A | 下一页 | 下一页（不变，接过 R1 的活） |
| PREV_PAGE | — | **未设置**（靠十字键 ← ↑） |

### 设置面板里的交互

「按键」区在面板最下面，每行 `功能　—　当前键`：
方向键选中 → A → 进入捕获（行内显示「按任意键…」）→ 按目标键即绑定；
捕获期间 **B 取消**，十字键等不可绑键会被忽略。

### 踩坑记录

- `Gamepad.actionOf` 改造时**一度把 B 从固定表里删掉**，导致 B 后退直接失效。
  正确做法：固定表里保留 `BUTTON_B -> BACK`，让它排在用户映射**之后**兜底 ——
  用户把 B 绑给别的动作时，上面查表先命中，B 就不再是后退（那种情况靠系统返回键）。
- `HELP_LINES` 从静态列表改成 `helpLines()` 动态生成，否则改完键位帮助还是旧的。

## v1.6.2：书库首页改版（Switch 式横排封面卡）

用户从三套 HTML 设计稿里选了「B 现代主机」：横排大封面卡 + 选中放大白描边 +
底部信息面板（书名/作者/章节/书签/进度）。落地后真机（BW0306C250002768）逐键验证通过。

### 键位（书库页独立于阅读器映射）

十字键选书 · **上键跳出卡片行到顶栏按钮（系统导航，按左右在「按键/导入」间切）** ·
**下键从顶栏回到当前选中的书** · A 打开 · **X 删除** · **L1/R1 整屏翻动（±5）** ·
Y 说明 · B 无操作。触摸行为不变（点按打开、长按删除）。
上键必须放行给系统 focusSearch；下键拦截自己 focusSelected()，否则系统会聚焦
「正下方」的任意卡片，选中位置漂移。

### 真机踩的坑

- **横向 RecyclerView 的 item 根绝不能 `match_parent`**：宽度会被撑成整屏，
  一屏只剩一张卡。必须 `wrap_content`（根只做垂直定位，卡片本体固定 104dp）。
- **焦点必须给卡片本体**：`focusSelected()` 一开始对根容器 `requestFocus()`，
  根没有 focusable → 静默失败，首页永远没有选中态。改给 `cardBox.requestFocus()`。
- **notifyDataSetChanged 后的聚焦时机**：普通 `post` 排在 vsync 的 doFrame **之前**，
  双 post 也一样早 → `findViewHolderForAdapterPosition` 拿到 null，焦点被顶栏按钮抢走。
  正确姿势：`recycler.doOnNextLayout { recycler.post { focusSelected() } }`。
- **AlertDialog 默认聚焦 destructive 按钮**：X 弹删除确认框，焦点自动在「删除」上，
  手柄 A 一下就误删。`showGamepadDialog()` 统一 show 后把焦点挪到取消侧；
  顺带挂了 OnKeyListener：A/确认 = 点焦点按钮，**B = 关闭**（dialog 是独立窗口，
  Activity 的 dispatchKeyEvent 收不到，这也是现存的通用坑）。
- 这块屏是 **hdpi（density 1.5）**：屏宽 640dp 不是 480dp，2dp 描边 = 3px 视觉太弱，
  选中描边给到 4dp，选中 scale 1.10 / 非选中 0.90 + alpha 0.8 对比才够一眼可辨。

### 「选中卡锁定屏幕正中」的实现要点（用户明确要求的交互）

- 十字键不能交给系统焦点导航 —— 它只会贴边滚。`dispatchKeyEvent` 自己拦截
  LEFT/RIGHT/L1/R1，统一走 `moveSelection(delta)`：requestFocus + 面板刷新。
- 居中 = 两个部分：**左右 padding = (屏宽-卡宽)/2**（scroll=0 时第一张正好居中，
  否则前几本书需要负向滚动、永远差一截）+ 焦点回调里
  `smoothScrollBy(卡中心x - 屏宽/2)` 平滑校正。**dx 方向**：卡中心减屏中心，写反了
  焦点卡会被滚出屏幕。
- 代价：初始停在第一本时左侧留白（Switch 主菜单同款），可接受。

### adb 安装的坑（这台设备）

`adb install`（streamed install）会报 `INSTALL_PARSE_FAILED_NO_CERTIFICATES:
SHA-256 digest did not verify` —— 和之前 push 中文文件名 md5 不一致是同一类传输损坏。
**这台设备装包必须 `adb install -r --no-streaming`**，本地 APK 本身签名正常。

### 《蛊真人》导入失败：两层根因（v1.6.3 修复）

**第一层：网文工具生成的非标准 zip。** 《蛊真人》EPUB 给 STORE 条目也标 data
descriptor 且 local header 全零 —— 桌面 JVM 的 ZipInputStream 直接抛
"only DEFLATED entries can have EXT descriptor"，但 **Android 的实现不抛**，
而是静默读出 **0 个条目**（有日志才定位到）。所以：
- 修法 = 兜底读 ZipFile（中央目录，宽容），但**触发条件不能靠异常**，必须校验
  结果：流式读出的 entries 里没有 OPF 就视为失败走兜底（`readEntries`）。
- 排查工具：把解析逻辑用桌面 Java 复刻 + `EpubParser` 加 Log + adb 自动化点击
  复现（tap 导入 → tap SAF 文件）→ logcat 看真机行为。

**第二层：readToc nav 分支的老 bug（OOM 元凶）。**
`resolvePath(nav.substringBeforeLast('/', ""), href)` —— `nav` 是**文件内容**
（235KB HTML）不是路径！每个目录项都把整个 nav 拼进路径 → 2347 次 × ~471KB
字符串分配 → 512MB 堆爆。ncx 分支当年修过同款坑（有注释），nav 分支漏了。
修法：`val dir = if (p.contains('/')) p.substringBeforeLast('/') else ""`。
OOM 定位靠 `showImportError` 里加 `Log.e("Import", "导入失败", e)` 看堆栈。

配套加固：`android:largeHeap="true"`（512MB 生效）；EpubParser 逐章
`entries.remove()`（几千章的书不再全量驻留）；readToc 用完即删 nav/ncx；
流式读 unconditional 消费每条 entry（超限图片也读掉丢弃，防流错位）；
错误文案人话化。**adb install 又遇 digest 损坏** —— /data/local/tmp 残留，
清理后 --no-streaming 成功。
